# Daily Journal Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repo, dispatch the `journal-backend` agent (`backend/.claude/agents/journal-backend.md`).

**Goal:** A FastAPI service over MongoDB Atlas that stores days, tasks and notes, carries unfinished tasks forward, and answers review and search queries.

**Architecture:** One FastAPI app in `backend/app`. Chain logic (carry-over, closing, delete) lives in `chains.py`; review counting is a pure function over task dicts in `review.py` so it is unit-testable without a database. Routes are thin. The database handle comes from a `get_db` dependency that tests override with a throwaway database.

**Tech Stack:** Python 3.12+, FastAPI, Pydantic v2, pydantic-settings, PyMongo ≥ 4.10 (`AsyncMongoClient`), uvicorn, uv, ruff, pytest, pytest-asyncio, httpx.

**Spec:** `todo_app/docs/design.md` (sections 3–6 and 9 are the backend's). Read it before Task 1.

## Global Constraints

- Work only inside `todo_app/backend`. It becomes its own git repo.
- Dates are `YYYY-MM-DD` strings in storage and JSON; never timestamps. The server never computes "today"; it takes `today` from the query string.
- Task status values: `open`, `done`, `dropped`.
- Task text: 1–500 characters, not whitespace-only, stored exactly as typed (no strip). Note text: 0–50 000 characters, stored exactly as typed.
- Ticket ID pattern: `\b[A-Z][A-Z0-9]+-\d+\b`.
- `_id` is exposed as string `id`; ObjectId values never appear in JSON.
- Errors use FastAPI's default `{"detail": ...}`; invalid input is 422, unknown id is 404.
- CORS allows exactly the origins in `CORS_ORIGINS`.
- Secrets live only in `.env` (git-ignored). `.env.example` has `MONGODB_URI=mongodb+srv://<user>:<password>@<cluster>/`, `MONGODB_DB=journal`, `CORS_ORIGINS=["http://localhost:5173"]`, `MONGODB_TEST_URI=`. Never print, log or commit the real URI.
- Tests never touch the `journal` database: each test session uses `journal_test_<8 hex>` and drops it afterwards.
- Every commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Opening today after a gap (Friday's open task, today is Monday): exactly one copy on Monday, `carried_days == 3`, nothing on Saturday or Sunday. Test in Task 3.
2. Two simultaneous `GET /api/days/{today}` requests: no duplicate copies. Test in Task 3.
3. A search query with regex metacharacters (`C++ (`, `.*`): literal match, no 500. Test in Task 6.
4. Invalid dates (`2026-13-40`, `today=yesterday`) and blank or 501-character task text: 422, nothing written. Test in Task 2.
5. Reopening a done chain whose latest copy is on an earlier day: the next load of today carries it again. Test in Task 4.

## Shared shapes (all tasks)

Task document in `tasks`:
`{_id, day, text, status, origin_id, prev_id, prev_day, origin_day, position, chain_status, chain_closed_on, created_at, updated_at}`
- `prev_id` / `prev_day`: `_id` and `day` of the copy this one was made from; both `None` for a new task.
- `origin_id`: `_id` of the first task in the chain (a new task sets it to its own pre-generated `_id`).
- `chain_status` (`open|done|dropped`) and `chain_closed_on` (day or `None`) are copied onto every task in the chain; `status` is the task's own.

`schemas.py`:
- `Status = Literal["open", "done", "dropped"]`
- `TaskCreate(text: str)` — validator: 1–500 chars, rejects whitespace-only, does not strip.
- `TaskPatch(text: str | None = None, status: Status | None = None)` — same text rule; at least one field required.
- `CommentIn(text: str)` — max 50 000.
- `TaskOut(id, day, text, status, origin_id, origin_day, prev_day: str | None, carried_days: int, chain_status: Status, chain_closed_on: str | None, chain_length: int, last_note: str | None = None)`
- `DayOut(date, tasks: list[TaskOut], comment: str, comment_updated_at: datetime | None, done: int, total: int, carried_in: int)`
  - `done` = tasks where `status == "done"` or `chain_status == "done"`; `total` = tasks where neither `status` nor `chain_status` is `"dropped"`; `carried_in` = tasks with `prev_id` not null.
- `ReviewItemOut(origin_id, text, day: str, open_days: int | None)`
- `ReviewDayOut(date, done: int, left: int)`
- `ReviewOut(start, end, done_count: int, remaining_count: int, days: list[ReviewDayOut], done: list[ReviewItemOut], remaining: list[ReviewItemOut])`
- `SearchHit(kind: Literal["task", "note"], task_id: str | None, text: str, status: Status | None)`
- `SearchGroupOut(date, hits: list[SearchHit])`; `SearchOut(query, groups: list[SearchGroupOut])`

### Task 3: Carry-over sync

**Files:**
- Modify: `app/chains.py`, `app/days.py` (call the sync)
- Test: `tests/test_chains.py`

**Interfaces:**
- Produces: `async sync_today(db, today: str) -> int` returning copies created. `GET /api/days/{date}` calls it only when `date == today`, before `load_day`.
- Algorithm (not determined by the tests alone):
  1. Aggregate `tasks` where `chain_status == "open"`, grouped by `origin_id`, taking the latest copy (max `day`, then its `position`).
  2. Keep groups whose latest `day < today`. Sort them by (latest day, position).
  3. Build one copy each: new `_id`, same `text`, `origin_id`, `origin_day`, `chain_status`; `day = today`; `prev_id` = latest copy's `_id`; `prev_day` = latest copy's `day`; `status = "open"`; positions continue from today's current max + 1, in sorted order.
  4. `insert_many(copies, ordered=False)`; catch `BulkWriteError` and ignore duplicate-key errors (code 11000) only, re-raising any other. Return the number actually inserted.
